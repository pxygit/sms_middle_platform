# SunnySMS Docker Deploy

This directory contains the production Docker deployment files for SunnySMS.

## Files

- `docker-compose.yml`: PostgreSQL, Go API, and Nginx web services.
- `.env.example`: deployment environment template.
- `.env`: generated by `../install.sh`; do not commit it.
- `nginx/default.conf`: serves the React build and proxies `/api/v1` plus `/health` to the API.
- `data/postgres`: PostgreSQL host data directory.
- `data/storage`: SunnySMS runtime storage, including card-code TXT exports.

## One-Command Install

Run this on a Linux server from the project root:

```bash
chmod +x install.sh
./install.sh
```

The installer checks:

- Linux host
- Docker Engine 24+
- Docker Compose v2+
- Docker daemon access
- configured HTTP port availability
- deployment environment file
- host data directories

On first run it creates `deploy/.env`, generates strong random values for PostgreSQL password, JWT secret, data encryption key, and default admin password, then starts all services.

## Configure Before Starting

You may edit `deploy/.env` before running `./install.sh` or before restarting services.

Important variables:

```env
SUNNYSMS_HTTP_PORT=8088
POSTGRES_DB=sunnysms
POSTGRES_USER=sunnysms
POSTGRES_PASSWORD=change-me
JWT_SECRET=change-me
DATA_ENCRYPTION_KEY=change-me
ADMIN_DEFAULT_USERNAME=admin
ADMIN_DEFAULT_PASSWORD=change-me
```

Supplier API keys can be configured either in `deploy/.env` before first startup or in the admin provider page after startup.

## Data Persistence

PostgreSQL data is mapped to:

```text
deploy/data/postgres
```

Runtime storage is mapped to:

```text
deploy/data/storage
```

Back up these directories before migration or server replacement.

## Common Commands

Run commands from the project root.

```bash
# Start or update after code changes
docker compose --env-file deploy/.env -f deploy/docker-compose.yml up -d --build

# Stop services
docker compose --env-file deploy/.env -f deploy/docker-compose.yml down

# View logs
docker compose --env-file deploy/.env -f deploy/docker-compose.yml logs -f

# Check status
docker compose --env-file deploy/.env -f deploy/docker-compose.yml ps
```

## PostgreSQL Backup

```bash
mkdir -p deploy/backups
docker compose --env-file deploy/.env -f deploy/docker-compose.yml exec -T postgres \
  pg_dump -U "$POSTGRES_USER" "$POSTGRES_DB" > deploy/backups/sunnysms_$(date +%F_%H%M%S).sql
```

If your shell does not load variables from `deploy/.env`, source it first:

```bash
set -a
. deploy/.env
set +a
```

## Notes

- The public site is exposed on `SUNNYSMS_HTTP_PORT`.
- The API service is not exposed directly to the host; Nginx proxies it internally.
- `deploy/.env` and `deploy/data/` should never be committed.
- If you put SunnySMS behind a reverse proxy, point the proxy to `http://127.0.0.1:${SUNNYSMS_HTTP_PORT}`.
